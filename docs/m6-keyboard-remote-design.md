# M6 键盘遥控设计——Mac 终端实时视图 + 按键回传（A 方案）

**状态：** 设计评审稿（2026-09-25）。用户已拍板 A 方案（看内容+发按键），开工前最后一轮确认。

**一句话**：Mac 上开着的终端窗口，手机上能实时看到内容，并且能"发送按键"——回车、Ctrl+C、输入一行命令再回车。不是终端仿真（M4 已定），是**遥控器**。

## 1. 用户体验

任务会话页新增「**终端遥控**」入口（选一个已配对 Mac 上正在运行的交互式会话）：

```
┌─ 终端遥控 ─────────────────────────┐
│  Mac 终端 — zsh                     │
│ ┌────────────────────────────────┐ │
│ │ (终端实时内容，滚动，只读)        │ │
│ │ $ tail -f server.log           │ │
│ │ ...                            │ │
│ └────────────────────────────────┘ │
│ ┌──────────────────────────────┐  │
│ │ [Ctrl+C] [↑] [Tab] [Ctrl+L]   │  │  ← 快捷键条
│ └──────────────────────────────┘  │
│ ┌──────────────────────────┐ [发] │
│ │ 输入命令…                  │      │  ← 文本行 + 发送（自动补 \n）
│ └──────────────────────────┘      │
└────────────────────────────────────┘
```

- **看**：终端内容实时流（复用 M4 的流式长连接，前端渲染成等宽文本）
- **发**：三种按键——控制键（Ctrl+C/L/D…）、方向/Tab、整行命令（文本+回车）
- **没有的**：方向键移动光标改历史命令、全屏 TUI 程序（vim/htop）的完整操控——这些需要终端仿真，超出 A 方案范围（做了会卡在渲染复杂度上）

## 2. 技术架构

### 2.1 Mac 端：受控 PTY 会话

- **新会话，不是接管用户已有终端**：Mac 端 TermiPad 自己 fork 一个 zsh 跑在 PTY 里（`forkpty` 或 PTY 库），手机连的是这个会话——**不碰用户在 Terminal/iTerm 里手开的窗口**（那是用户私人领地，接管它既危险又复杂）
- PTY 输出 → 逐段走 M4 已有的流管道（TaskOutputStreamService 扩展一个 stream 类型：`shell`）
- PTY 输入 → 收手机按键/文本，`write` 进 PTY master
- **生命周期绑定每日窗口**：窗口关闭/锁屏 → PTY 收到退出信号 + 流断开（复用 M3/M4 全套钩子）
- 进程纪律：PTY 创建限定在新文件 `TerminalRemoteService.swift`（Process 白名单第五个文件）

### 2.2 协议增量

```
openShellStream                     （手机→Mac：订阅 shell 流，Mac 创建 PTY）
shellKey(streamID, key)             （手机→Mac：控制键，如 "C-c" / "Return" / "Tab"）
shellLine(streamID, text)           （手机→Mac：整行命令，Mac 补 \n 写入）
流输出复用 MobileStreamChunk
closeShellStream                    （手机→Mac：退出会话，PTT 内 kill shell）
```

全部走既有帧+AEAD；每日窗口前置（复用 M4 裁决）；速率限制覆盖按键。

### 2.3 手机端

- 终端遥控页：内容视图（复用流渲染）+ 快捷键条（横向滚动按钮）+ 文本输入行
- 按键用系统键盘配套：文本行用 `.keyboardType(.asciiCapable)`，"发送"= shellLine
- 快捷键条按钮 → shellKey；Ctrl 组合用长按或专用按钮

## 3. 安全边界（继承 + 新增）

| 防线 | 状态 |
|---|---|
| 每日窗口 | ✅ 开窗才能开 shell；锁屏即杀 PTY |
| 锁屏拒绝 | ✅ |
| 速率限制 | ✅ 按键也计入 |
| 输出脱敏 | ✅（注意：终端内容脱敏会破坏命令回显的一部分可用性——restricted 档位下对 shell 流只脱敏已知密钥模式，用户知情） |
| **新增：PTY 进程即任务** | shell 会话有超时（默认 30 分钟无输入自动退出）、挂进程数 1（新开踢旧） |
| **新增：明确告知** | 手机上会话页显示"这是 Mac 上 TermiPad 拉起的独立 shell，不是你已有的终端窗口" |

**诚实风险声明**：手机发整行命令 = 在 Mac 上执行任意命令。这就是 A 方案的本质（用户已拍板接受）。缓解全靠：每日窗口 + 锁屏即杀 + Face ID app 锁 + 凭据时效。**丢手机 + 已解锁 + 窗口开着** = 对方能跑命令——这是这个功能的固有代价，写进设计让你知情。

## 4. 验收（G9）

| # | 项 | 标准 |
|---|---|---|
| 1 | 看内容 | 手机连上后能看到 PTY shell 的提示符与命令回显 |
| 2 | 发按键 | Ctrl+C 能中断前台命令；整行命令+回车能执行 |
| 3 | 窗口绑定 | 关窗/锁屏 → PTY 即杀、流断 |
| 4 | 隔离 | 与用户自己的 Terminal 窗口互不影响 |
| 5 | 脱敏 | 终端输出 token → 手机端已打码 |
| 6 | 红线 | Funnel/公网仍禁；PTY 仅 TermiPad 拉起；协议无路径字段 |
